# EvonyMasters: private Google Sheets integration (development only)

This folder is a **separate Cloudflare Worker** proof of concept. The production Astro app remains unchanged. Data is **not** published as CSV and the Google Sheet stays private.

## Components
- `worker.mjs`: HMAC-authenticated receiver `POST /v1/sync`, no bulk-download endpoint, and bounded `GET /v1/search?q=...`.
- `apps-script.gs`: a **spreadsheet-bound** script running as the authorized Google user, sending a complete snapshot every five minutes.
- KV namespace `DATA` stores **only the latest successfully validated snapshot**; rejected imports leave the previous snapshot intact.

## Setup (manual account-owner steps)
1. Keep the ITEM FINDER spreadsheet private. Do not publish to web or allow link-wide access.
2. Create a **separate** Cloudflare Worker named `evonymasters-sheet-sync` using `worker.mjs`. Do **not** replace the existing `evonymasters` Worker.
3. In Cloudflare, create a Workers KV namespace and bind it to the sync Worker as `DATA`. Configure `SYNC_SECRET` as a Worker **secret** containing a new unpredictable random value (e.g. generated by a password manager). Never commit the value to GitHub.
4. Within the ITEM FINDER Google Sheet choose Extensions → Apps Script. Paste `apps-script.gs`; update `SYNC_URL` to your new Worker's URL. In Apps Script Project Settings → Script properties, create `SYNC_SECRET` with the **same** value. Scripts need edit access to the workbook; only trusted collaborators should edit scripts.
5. Run `setupSync` once in Apps Script and approve the requested Google permissions. Then test `https://<new-worker-host>/v1/search?q=refining%20stone`. The script sets a five-minute time trigger. There is no publicly accessible Sheets URL.
6. Review the trial search results and nested-box behavior before changing the live Resource Finder. Set Cloudflare security/rate-limiting rules for `/v1/search` if available. Requests should never expose full underlying records.

## Data mapping
- EVENTS & ACTIVITIES: header on row 2, relevant columns EVENT NAME / ITEM / QUANTITY and activity metadata.
- MONSTERS: header on row 1, Monster Name / Reward Item (in-game) / Quantity / Drop Classification, type/level/power/stamina/event.
- IN THE BOXES: header on row 2, Box Name → Reward Item (in-game) / Quantity / Drop Classification. Referenced box names resolve recursively with a cycle guard. A reward through a `Possible` chest remains possible.
- Quantities are preserved as displayed strings so `Variable`, commas, and other source values are not silently changed.

## Important limitations before production
- This is intentionally a **staging data service**, not a production-ready replacement for the website. The current Astro site still embeds GitHub JSON in HTML; publishing this branch alone does not stop scraping of that existing data.
- The public search endpoint exposes matching records and can still be scraped by repeated searches. No website can fully prevent collection of visible information. Add Cloudflare abuse controls, and return minimal fields.
- HMAC protects pushes in transit; HTTPS is required. Timestamps within five minutes are accepted, so duplicate/replay pushes during that window are possible. For stronger threat models, add nonce replay protection.
- At five-minute intervals the script makes 288 sync attempts/day. Check Apps Script and Cloudflare Free quota and spreadsheet size; KV write quotas and Worker CPU/requests may change.
- The importer requires every populated event row to have EVENT NAME and ITEM, every populated monster row to have Monster Name and Reward Item, and every populated box row to have Box Name and Reward Item. Correct invalid spreadsheet rows before syncing.
- Avoid storing private information in the reward sheet: the search API is publicly callable, even though the spreadsheet itself is private.
- No deployment, secrets, KV namespace, or production integration is performed by this commit.
